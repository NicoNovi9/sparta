SUBJECT: H200 jobs fail with "out of memory" - GPU memory seen fully used by cuda_memtest

Hello,

This is a follow-up to my earlier ticket about my jobs failing on the H200
nodes. I have collected more observations, described below. I have not
established the cause, so I would be grateful if you could look into it.

What happens
My application (SPARTA, running on a single H200 GPU) stops with a CUDA
"out of memory" error. It happens at a different moment in every run, always
within the first few minutes, although the application itself uses only about
5 GB of the 141 GB available. The same job completes normally on the V100
nodes.

What I observed
I ran a job on node an6006 (job 1212041) that recorded, several times per
second, how much memory was in use on my assigned GPU and which processes were
using it. For the first 5 minutes of the job my application was not running,
so the GPU should have been idle.

During those idle minutes, the GPU memory became completely full twice, each
time for less than a second. At those moments nvidia-smi listed a process
called /hpc/shared/bin/cuda_memtest using almost the entire GPU memory.

The same thing happened again about 5 minutes later, shortly after my
application had started, and my application failed at that moment with the
out-of-memory error.

In earlier jobs on the same nodes I had also seen the GPU memory briefly
reach its full capacity just before each failure.

Two other things I noticed on an6006, in case they are relevant: the kernel
log shows GPU error messages (Xid 94) on the same GPU I was assigned, and the
H200 nodes run an older NVIDIA driver than the V100 nodes.

Questions
- What is cuda_memtest, and is it expected to run on a GPU that is assigned
  to a running job?
- Could it be the cause of the out-of-memory failures on the H200 nodes?

I have the full recordings from the job and can send them if useful.

Thank you,
Nicola Noventa
